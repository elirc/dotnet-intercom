# Module 06: Contribution Practice

> **Simulated OSS workflow.** This repo is synthetic — no real maintainers or issue tracker ([provenance](../08-reference/verification-log.md)). You play the contributor; these tickets encode a maintainer's bar. Branch per ticket, write tests, open PRs against your fork. The skills are real even though the project isn't live.

A ladder from "make a safe change" to "design a subsystem."

| Page | Level | What you practice |
| --- | --- | --- |
| [01-good-first-tickets.md](01-good-first-tickets.md) | Junior | Small safe changes using existing patterns (10 tickets) |
| [02-mid-level-feature-tickets.md](02-mid-level-feature-tickets.md) | Mid | Cross-layer features with design notes, risk, rollback |
| [03-senior-build-projects.md](03-senior-build-projects.md) | Senior | Subsystem design with migration/test/security/rollout plans |
| [04-refactor-and-design-katas.md](04-refactor-and-design-katas.md) | Mixed | Targeted refactors + an RFC + a flawed-PR review, each self-graded |

Work them in order; each level assumes the patterns you internalized at the previous one. Don't skip the tests — "it compiles" is never the bar here.
